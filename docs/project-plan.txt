Pulse — Project Plan
Oct 8, 2026 · @onemoretime
Verdict
Pulse is a good project: small enough to ship, visual enough to stay motivating, and deep enough to teach real architecture. The original plan gets the order right (fake data, then animation, then real notifications) but skips the three Linux problems that decide whether the app can exist at all.
What the original plan gets right:
• UI and animation first, with fake notifications, before any D-Bus work.
• A Python core (queue, priority, rules, history) that is testable without the UI.
• Themes as data, never code; plugins kept separate with permissions.
• Notification types (message, progress, media, level) instead of one generic popup.
What it misses or gets wrong:
• Window placement on Wayland. A normal Qt window cannot pin itself to the top-center of the screen or stay above everything on Wayland. CachyOS defaults to Wayland sessions. This is the first thing to solve, not version 0.85.
• Who owns the notification bus. Only one program can own org.freedesktop.Notifications. On KDE Plasma and GNOME, the desktop shell already owns it, so Pulse cannot simply "implement" it there.
• Blur. An app cannot blur what is behind its own window. Background blur is a compositor feature, so "blur": 18 in a theme only works where the compositor cooperates.
• Click-through. A transparent always-on-top window blocks clicks on whatever it covers unless you set an input region.
• Roadmap granularity. Twenty-five numbered versions invite scope creep. Five milestones with clear exit criteria are easier to finish.
The fix is a one-week technical spike before any polish work (Milestone 0 below).

1. Window placement
Wayland does not let ordinary windows choose their position or stay above others. Bars and overlays use the layer-shell protocol instead: the window anchors to a screen edge on the "overlay" layer.
Routes from Python, in order of preference:
1. LayerShellQt as a Qt shell plugin. KDE's layer-shell-qt can be loaded through QT_WAYLAND_SHELL_INTEGRATION=layer-shell, which may let a PySide6 window become a layer surface without C++ bindings. Verify this works with your installed version during the spike.
2. XWayland fallback. Run with QT_QPA_PLATFORM=xcb and use FramelessWindowHint | WindowStaysOnTopHint | Tool. Fine for prototyping; less reliable across compositors.
3. Change toolkit. GTK4 + gtk4-layer-shell via PyGObject is a proven Python route, at the cost of QML's animation system.
2. Notification bus ownership
Pulse can run in two modes. Design the adapter so both fit behind the same interface.
• Daemon mode (full features): Pulse owns org.freedesktop.Notifications, returns IDs, handles replacement, actions and CloseNotification, and emits NotificationClosed / ActionInvoked. Works on Hyprland, Sway and similar.
• Observer mode (read-only): Pulse watches Notify calls on the session bus with a D-Bus monitor and mirrors them. The shell still shows its own popup, and actions cannot be answered. This is the only clean option on KDE and GNOME.
3. Blur and click-through
• Treat blur as an optional, compositor-specific extra. The default "glass" look is a translucent dark fill with a subtle border, which works everywhere.
• Keep the window a fixed size (the largest the island can grow) and animate the shape inside it. Resizing the real window every frame causes stutter.
• Set an input region (QWindow.setMask) that matches only the visible island, so clicks around it pass through to the desktop.

Keep Python + PySide6 + QML, provided Milestone 0 proves the window can be pinned on your desktop. The core rule: everything under core/ is plain Python with no Qt UI imports, so it can be tested in isolation.

Core logic and controller signals
Data flows one way. Sources produce events, the core decides what deserves the island, the controller turns that into state, and QML only renders state. QML never calls D-Bus, and the core never knows what a theme is.
Themes reach only the QML layer, and history hangs off the core; swapping a source (daemon for observer, Linux for Windows later) touches nothing to its right.
Animation design
The island is one shape that changes size, never a series of popups. A single rounded rectangle holds the current content; its width, height and corner radius follow the state, and content cross-fades inside it.
Rules that make it feel fluid:
• Retarget, don't restart. If a new notification arrives mid-exit, the shape should turn around from its current size. Spring-based Behavior on width/height does this naturally; fixed-duration transitions jump.
• Shape leads, content follows. On entry, content fades in once the shape is about 70% grown. On exit, content fades out first, then the shape shrinks.
• Size comes from content. Measure the text (implicitWidth, TextMetrics), then clamp between a minimum pill and a maximum width. Long bodies elide or wrap to two lines.
• Presets are data. An animation preset is a named set of numbers (duration, easing, overshoot, stagger). Themes pick a preset by name; they never contain animation code.
• Reduced motion. One setting that swaps every preset for short fades.

Roadmap
Six milestones replace the 25 version numbers. Never start a milestone until the gate above it passes; that rule is what keeps the project finishable.
M1 is where most of the effort should go. If the island does not feel great with fake data, real notifications will not fix it.

Prior art worth reading before you start. Quickshell is a QtQuick toolkit for desktop widgets with layer-shell, a notification server, MPRIS and PipeWire built in. It solves most of Milestone 0 and 1 in pure QML, at the cost of writing logic in QML/JS rather than Python. Read a few Quickshell configs for animation ideas even if you stay with Python; projects like hare show the expected setup, including stopping mako or dunst so the notification server can register.

First session checklist
The first session ends when a black pill sits at the top-center of your screen, above other windows, and clicks pass through around it. No notifications yet.
[ ] Note your session: echo $XDG_SESSION_TYPE $XDG_CURRENT_DESKTOP
[ ] Create the repo, a virtualenv and pyproject.toml; install PySide6, qasync, pytest, pytest-qt
[ ] Load a QML file with a transparent, frameless window and a 30 px rounded pill
[ ] Try layer-shell: install layer-shell-qt, run with QT_WAYLAND_SHELL_INTEGRATION=layer-shell, check anchoring and overlay layer
[ ] If that fails, try QT_QPA_PLATFORM=xcb with stay-on-top flags and record what breaks
[ ] Set an input mask to the pill's rectangle; confirm you can click the window underneath
[ ] Bind a key or timer that toggles the pill between 30 px and 300 × 64 px with a spring animation
[ ] Write down which route worked; that decides the toolkit for Milestone 1
